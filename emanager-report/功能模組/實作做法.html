eManagerReport 實作做法

如何利用現有框架新增或修改報表、資料來源、權限設定
說明如何利用現有框架新增或修改報表、資料來源、權限設定等。大多數情境僅需在資料庫設定，無須改動程式碼；新增資料來源與零值過濾規則則需改 code。

1. 新增一張報表（不改程式碼）

所有設定都透過資料庫完成，依序插入以下資料表：

Step 1：Report_Basic — 建立報表基本資訊

INSERT INTO [Report_Basic]
    ([ReportID], [Name], [ReportCode], [ReportType], [ReportSort],
     [StartYear], [MaxLevel], [isDefaultLevel], [CurrencyUnitRemark],
     [RedirectText], [RedirectUrl])
VALUES
    (NEWID(), '報表名稱', 'OSF', 'Classic', 1,
     '2024', 3, 0, '($K)',
     NULL, NULL)
  • ReportCode：OSF / HC Dashboard / CRM（決定資料來源）
  • ReportType：Classic / MultipleReportView
  • isDefaultLevel：1 = 依使用者權限決定預設層；0 = 固定從 Level 1 開始
  • MaxLevel：最深層級數，影響「全部選擇後」停在哪層

Step 2：Report_Level — 定義層級

每一層一筆，LevelColumnName 必須對應資料來源中實際使用的欄位名稱：

INSERT INTO [Report_Level]
    ([ReportID], [Level], [LevelColumnName], [FilterName], [ShowFilter], [hasPermission])
VALUES
    (@ReportID, 1, 'Sector', 'Sector', 1, 0),
    (@ReportID, 2, 'Region', 'Region', 1, 0),
    (@ReportID, 3, 'Entity', 'Entity', 1, 0)
  • ShowFilter：前端是否顯示此層篩選器
  • hasPermission：是否對此層啟用 Measure 層級權限控管

Step 3：Report_Dimensions — 定義橫向維度欄

INSERT INTO [Report_Dimensions]
    ([ReportID], [GroupName], [Name], [Sort], [DisplayGroup], [IsDefault])
VALUES
    (@ReportID, 'Monthly', 'Jan', 1, 'Monthly', 1),
    (@ReportID, 'Monthly', 'Feb', 2, 'Monthly', 1),
    -- ...
    (@ReportID, 'Summary', 'YTD',  13, 'Summary', 1),
    (@ReportID, 'Summary', 'Year Total', 14, 'Summary', 1)

Step 4：vw_Report_Measures（底層資料表）— 定義縱向 Measures

INSERT INTO [Report_Measures]
    ([ReportID], [Level], [Name], [Sort], [Year],
     [FontColor], [BackgroundColor], [DisplayGroup], [ParentName], [FilterColor])
VALUES
    (@ReportID, 1, 'APAC', 1, '2025', NULL, NULL, NULL, NULL, NULL),
    (@ReportID, 1, 'EMEA', 2, '2025', NULL, NULL, NULL, NULL, NULL)

Step 5：Report_Measures_KPIs — 定義 KPI 欄位

INSERT INTO [Report_Measures_KPIs]
    ([ReportID], [Level], [Name], [DisplayName], [Sort], [Unit], [DecimalPoint],
     [FontColor], [BackgroundColor],
     [CompareCategory], [CompareType], [Compare], [CompareStyle],
     [URL], [IsDefault], [Permission], [needEmpty],
     [CurrentMonthZero], [PastMonthsAdjustment], [FutureMonthsAdjustment])
VALUES
    (@ReportID, 1, 'CurrentYear Achv.', 'CurrentYear Achv.', 1, '$K', 0,
     NULL, NULL,
     NULL, NULL, NULL, NULL,
     NULL, 1, 0, 0,
     0, NULL, NULL)
  • Name 支援 CurrentYear / LastYear 佔位符，框架自動轉換為實際年份
  • Permission = 1 表示啟用 KPI 層級權限控管

2. 新增 MultipleReportView（多 Tab 報表）

同一 ReportCode 下，多張報表都設定 ReportType = 'MultipleReportView'：

-- Tab 1
INSERT INTO [Report_Basic] VALUES (NEWID(), 'Sales Performance', 'OSF', 'MultipleReportView', 1, ...)
-- Tab 2
INSERT INTO [Report_Basic] VALUES (NEWID(), 'SBU Performance',   'OSF', 'MultipleReportView', 2, ...)

框架會查詢同 ReportCode 的所有 MultipleReportView 報表，前端 JS 依 ReportSort 排序顯示 Tab。

3. 設定三層權限

Layer 1：Level 權限

修改 vw_Report_Level_Permission 的底層資料（視 View 定義決定資料表）。DefaultLevel 決定使用者進入報表時預設看哪層；RequiredPermissionLevelsList 決定允許切換的層級範圍。

Layer 2：Measure 權限

在底層資料表（vw_Report_Measures_Permission 底層）插入記錄：

-- 授權特定 Measure
INSERT INTO [底層資料表] ([ReportID], [Level], [Email], [Name])
VALUES (@ReportID, 2, 'user@company.com', 'APAC')

-- 授權全部（ALL）
INSERT INTO [底層資料表] ([ReportID], [Level], [Email], [Name])
VALUES (@ReportID, 2, 'user@company.com', 'ALL')

同時需將 Report_Level.hasPermission = 1 以啟用該層的過濾。

Layer 3：KPI 權限

基本用法：指定使用者只能看某些 KPI

INSERT INTO [Report_Measures_KPIs_Permission]
    ([ReportID], [Level], [Email], [Name], [LastLevelMeasures], [CheckLevel], [Measures])
VALUES
    (@ReportID, 2, 'user@company.com', 'CurrentYear Achv.', NULL, NULL, 'APAC')

進階用法：依上層選擇動態決定

-- 只有第 1 層選了 'APAC' 時，第 3 層才顯示此 KPI
INSERT INTO [Report_Measures_KPIs_Permission]
    ([ReportID], [Level], [Email], [Name], [LastLevelMeasures], [CheckLevel], [Measures])
VALUES
    (@ReportID, 3, NULL, 'CRM Pipeline', 'APAC', 1, NULL)
欄位說明
Email 為空套用所有使用者
LastLevelMeasures 為空不限制，直接依 Measures 欄位決定
CheckLevel 為空預設對照上一層（Level - 1）
Measures 為空不限制當前層的 Measure

同時需將 Report_Measures_KPIs.Permission = 1 以啟用此 KPI 的權限控管。

4. 新增 KPI SpecialRule（特定格子改顯示固定文字）

當特定 Measure 在特定 Dimension 下，某 KPI 不顯示計算值而改用固定文字時：

INSERT INTO [Report_Measures_KPIs_SpecialRule]
    ([ReportID], [KPIName], [Dimensions], [SpecialRule], [DisplayValue])
VALUES
    (@ReportID, 'CurrentYear Achv.', 'Year Total', 'FixedText', 'N/A')

5. 設定 RedirectUrl（外連按鈕）

在 Report_Basic 設定：

UPDATE [Report_Basic]
SET [RedirectText] = '查看詳細',
    [RedirectUrl]  = 'https://other-system.com/report?user={Email}&token={EZTicketId}'
WHERE [ReportID] = @ReportID

框架渲染時自動替換 {Email} 和 {EZTicketId}。RedirectText 和 RedirectUrl 需同時有值才會顯示按鈕。

6. 新增資料來源（需改程式碼）

需要修改三個地方：

Step 1：新增 Repository 方法

在 ReportSourceRepository.cs 新增查詢方法，參考現有的 GetOSFDashboard / GetHCDashboard：

public async Task<IEnumerable<MyDataSource>> GetMyDashboard(
    ReportFilter reportFilter,
    Dictionary<string, List<string>> FilterColumn)
{
    using (var Connection = _SomeDatabaseHelper.GetDbConnection())
    {
        var SQL = @"SELECT ... FROM [MyTable] WHERE 1=1 ";
        foreach (string col in FilterColumn.Keys)
        {
            SQL += FilterColumn[col].Count >= 1
                ? $"AND [{col}] IN ('{string.Join("','", FilterColumn[col])}') "
                : "";
        }
        Connection.Open();
        return await Connection.QueryAsync<MyDataSource>(SQL, new { reportFilter.Year });
    }
}

在 IReportSourceRepository 介面新增對應宣告。

Step 2：新增 DataSource Model

在 eManagerCore.Models/DataModels/eManager/ReportSource/DataSource/ 新增 Model 類別。

Step 3：在 GetReportSources 新增 case

在 ReportStructureService.cs 的 GetReportSources() 的 switch (ReportCode) 中新增：

case "MY_SOURCE":
    var myData = await _reportSourceRepository.GetMyDashboard(Report.ReportFilter, FilterColumn);
    foreach (var item in myData)
    {
        ReportSource.Add(new ReportSourceItem
        {
            Currency = item.Currency,
            Year     = item.Year,
            Dimensions = item.Dimensions,
            Measures = item.Measures,
            KPI      = item.KPI,
            Value    = item.Value
        });
    }
    ReportCurrency.AddRange(myData.Select(x => x.Currency).Distinct().OrderBy(x => x));
    break;

在 Report_Basic 中，新報表的 ReportCode 設為 "MY_SOURCE"。

7. 新增零值 Measures 過濾規則（需改程式碼）

在 ReportStructureService.GetReport() 的 switch 段落新增：

// 依 ReportCode 觸發
case "MY_SOURCE":
    ShipmentRegionNonZero = ReportSources.DataSource
        .Where(x => x.KPI == "某KPI" && x.Dimensions == "某維度")
        .Where(x => x.Value != 0)
        .Select(x => x.Measures)
        .Distinct().ToList();
    break;

或在 switch (reportBasic.Name) 中依報表名稱觸發。

8. KPI DisplayName 與 Name 的關係

  • Name：框架用來比對資料來源資料的欄位名稱（可含佔位符）
  • DisplayName：前端顯示的名稱

同步轉換（Name == DisplayName 時）：框架偵測到兩者相同，DisplayName 跟 Name 一起做年份轉換。

獨立顯示：DisplayName 與 Name 設為不同值，則 DisplayName 固定不轉換，Name 仍做比對轉換。

9. 前端觸發報表重整

前端只需更新 select[name="MeasuresItem"] 的值並呼叫 loadReportStructure()，框架會自動收集所有篩選條件並跳轉：

// 手動觸發重整
var reportFilter = checkFilterInformation();
loadReportStructure(reportFilter);

10. 注意事項

  • KPI 名稱中有 Non-Breaking Space：直接在 DB 修改字元，或確保插入前已 normalize，否則年份轉換比對會失敗。
  • 新增資料來源：FilterColumn 的 key 必須對應 Report_Level.LevelColumnName，框架自動組成 SQL 的 IN 條件。
  • HC Dashboard 的 SpecialKPI：Last Year HC 和 H/C Budget 是程式內計算產生，View 端需要另外處理顯示，不走一般的 DataSource 取值邏輯。
  • CRM Level >= 4：ReportSpecialKPI 存的是可讀名稱（SalesName / AccountName），View 端需用 Measures 值當 key 去取可讀名稱顯示。
