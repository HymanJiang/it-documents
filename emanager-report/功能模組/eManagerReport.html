ASP.NET Core MVC Dapper ScoreCard Area OSF / HC / CRM

1功能概述

eManagerReport 是 Advantech eManager ScoreCard 的核心報表模組，提供各層級主管查閱業績績效數據的統一入口。 報表結構（層級、欄位、KPI）全部存於資料庫，新增報表不需修改程式碼。

4權限系統

系統採三層疊加式權限，每層獨立設定：

Layer 1：Level 權限

控制使用者可查看哪個層級的資料。來源：vw_Report_Level_Permission。 若 DefaultLevel = 0 代表無存取權，回傳空報表。

Layer 2：Measure 權限

控制使用者在每個層級可見哪些組織/業務單位列。來源：vw_Report_Measures_Permission。 特殊值 "ALL" 代表可見該層級全部 Measures；無設定代表不限制。

Layer 3：KPI 權限

控制使用者可見哪些 KPI 欄位。Email 為空 = 通用規則；有值 = 個人規則。 LastLevelMeasures 有值時，依 CheckLevel 指定的層級選擇值動態決定 KPI 是否顯示。 CheckLevel 為空時預設對照上一層（Level - 1）；有值時可指定任意層，例如永遠對照第一層。

CheckLevel 判斷邏輯

KPI.Permission = false
  └─ 永遠顯示

KPI.Permission = true，且任一筆 Permission 記錄的 LastLevelMeasures 為空
  └─ 顯示（不限制）

KPI.Permission = true，且所有 Permission 記錄的 LastLevelMeasures 都有值
  └─ 逐筆檢查（ANY 符合即顯示）：
       checkLevel = 該筆 CheckLevel ?? (當前 Level - 1)
       ├─ 使用者在 checkLevel 的選擇值 == LastLevelMeasures → 顯示
       ├─ 使用者尚未在 checkLevel 做選擇 → 顯示（預設開放）
       └─ 全部不符合 → 隱藏

CheckLevel 設定範例

需求：第三層時，只有第一層選了「A」才顯示某 KPI

欄位值
Level3
NameKPI 名稱
CheckLevel1（對照第一層）
LastLevelMeasuresA
Measures（空 = 不限制當前層）
Email（空 = 全員）

KPI 權限查詢 SQL 設計

SELECT * FROM (
    -- 全員通用規則
    SELECT * FROM [Report_Measures_KPIs_Permission]
    WHERE [ReportID] = @ReportID AND ISNULL([Email],'') = ''
    UNION ALL
    -- 個人專屬規則
    SELECT * FROM [Report_Measures_KPIs_Permission]
    WHERE [ReportID] = @ReportID AND ISNULL([Email],'') = @Email
) A
WHERE [Level] = @Level

兩者 UNION ALL 合併後再篩 Level，同一個 KPI 可同時擁有「預設規則」與「個人覆寫規則」。

5資料流程

完整請求流程

1
使用者互動 點擊報表連結或調整篩選條件（Year / Currency / Measures）
↓
2
eManagerReport.js 收集 reportId、Year、Currency 及各層級 Measures 選擇（格式："{Level}-{Value}"）
↓
3
GET /ScoreCard/Home/eManagerReport/{reportId} 帶入 ReportFilter query parameters
↓
4
HomeController.eManagerReport() 驗證 reportId、補齊預設值（Year=當年、Currency=USD、Level=1）、反序列化 MeasuresJson
↓
5
ReportStructureService.GetReport() 平行抓取基礎設定 → 計算 Level → 取 Dimensions / Measures / KPIs / 業績資料 → 過濾零值
↓
6
View 渲染 Classic → ClassicReport.cshtml ／ MultipleReportView → MultipleReportView.cshtml

Level 決定邏輯

初次載入（無 MeasuresValue）：
  isDefaultLevel = true  → 使用 Permission.DefaultLevel（無權限則 Level = 0）
  isDefaultLevel = false → Level = 1

使用者有選擇（有 MeasuresValue）：
  找第一個值為 "ALL" 的 Level → 使用該 Level
  都不是 "ALL"               → 使用 MaxLevel

  + 套用 Level 權限：
    從授權清單找 >= 當前 Level 的最小值

6資料來源

OSF — Order / Shipment / Forecast

業務出貨與業績達成率，支援多幣別。Level 1 → Sector、Level 2 → Region、Level 3+ → Entity。額外處理 YTM Local Currency 邏輯。

HC Dashboard — Human Capital

人力編制追蹤，固定幣別 USD。額外計算 Last Year HC（上年 Dec 快照）與 H/C Budget（Budget 維度快照）。

CRM — Customer Relationship Management

業務銷售管道，支援多幣別。Level 1→Region、2→Sector、3→SalesTeam、4→SalesId、5→Account。Level ≥ 4 自動對應可讀名稱。

OSF Level 對應

LevelMeasures 欄位
1Sector
2Region
3+Entity

CRM Level 對應

LevelMeasures 欄位
1Region
2Sector
3SalesTeam
4SalesId → 顯示 SalesName
5Account → 顯示 AccountName

零值 Measures 過濾規則

報表過濾條件
Sales Performance（Name）{Year} Achv. 在 Year Total 維度值為 0
HC Dashboard（ReportCode）Revenue 在 YTM 維度值為 0
CRM（ReportCode）Achivement 在 Year Total 維度值為 0

8前端互動

eManagerReport.js

負責從畫面收集篩選條件並觸發頁面跳轉：

  • 監聽 Measure 列的點擊事件
  • 收集 Year、Currency、各層級 Measures 選擇
  • 將 Measures 組成 "{Level}-{Value}" 格式的 Array
  • 導向 /ScoreCard/Home/eManagerReport/{reportId}?... 帶入所有篩選

MultipleReportView.js

在 eManagerReport.js 基礎上，增加 Tab 切換功能：

  • 監聽報表 Tab 標籤點擊
  • 切換 Tab 時更新 FilterBox 中的 reportid
  • 其餘篩選邏輯沿用 eManagerReport.js

9特殊處理邏輯

KPI 名稱年份動態轉換

Service 層每次查詢時依 reportFilter.Year 建立轉換字典：

原始 KPI 名稱轉換後（以 2025 年為例）
LastYear Actual2024 Actual
CurrentYear Quota2025 Quota
CurrentYear Achv.2025 Achv.
CurrentYear Backlog2025 Backlog
LastYear Digital Actual %2024 Digital Actual %
CurrentYear Digital Actual %2025 Digital Actual %
2025Shipment2025 Achv.
2024Shipment2024 Actual

非斷行空白 (Non-Breaking Space) 處理

KPI 名稱若混入 Unicode  （字元碼 160），會導致 Dictionary 比對失敗。Service 在轉換前先 normalize：

var normalizedName = originalName
    .Replace(' ', ' ')  // Non-Breaking Space → 標準空白
    .Trim();

FilterColumn 的 "null" 字串清理

前端若傳入字串 "null" 作為篩選值，Service 在建立 FilterColumn 後會自動移除，避免傳入 DB 查詢造成錯誤。

RedirectUrl 佔位符替換

Report_Basic.RedirectUrl 支援以下佔位符，在 NewReportStructure() 渲染時自動替換：

佔位符替換內容
{Email}當前使用者（或模擬使用者）的 Email
{EZTicketId}使用者的 EZTicket 單一登入 Token

OSF Local Currency 邏輯

YTM Total 維度的資料需依 Region 對應本地幣別，轉為 YTM Local $ 維度顯示。 Rolling Forecast 與 Forecast Achv. % 兩個 KPI 不參與此處理。
