一、人員管理

Q如何新增一位業務員？
  1. 前往「業務員管理」頁面，點擊「新增業務員」。
  2. 填入 AD 帳號（Email 格式）、顯示名稱、所屬 Site（ATW / HQDC / BO）。
  3. 設定 角色（Sales / Leader / BO），影響 Over Quota 計算比率與全年所得上限。
  4. 設定 BonusCurrency（實際發放幣別）與 DefaultDisplayCurrency（報表預設顯示幣別）。兩者可以不同，例如發放 TWD 但報表預設顯示 USD。
  5. 儲存後，系統的每日同步 Job 會在下次執行時自動從公司內部系統帶入對應的 Sales ID 記錄。
Sales ID 由同步 Job 自動帶入，無需手動輸入。新增業務員後，至遲隔日同步完成即可開始設定 Plan。
Q業務員的角色對計算有什麼影響？要如何選擇？
角色Over Quota 100–120% 加成Over Quota >120% 加成全年所得上限
Sales（預設）+1%+0.5%TCP × 5 倍
Leader / Sales Manager+0.5%+0.3%TCP × 3 倍
BO+0.5%+0.3%TCP × 3 倍

角色的主要差異在於超額獎金加成率及全年所得上限。一般業務員選 Sales；有管轄下屬並負責團隊業績者選 Leader；BO 通路主管選 BO。

QBonusCurrency 和 DefaultDisplayCurrency 有什麼差異？
  • BonusCurrency：財務實際發放獎金使用的幣別，影響計算引擎的最終輸出。例如台灣業務員發 TWD，就填 TWD。
  • DefaultDisplayCurrency：業務員進入報表頁面時，系統預設顯示的幣別。純粹影響 UI，不影響計算。例如某業務員慣用 USD 對帳，可設為 USD，但獎金仍以 TWD 發放。
兩者相同是最常見的設定。只有當業務員日常對帳使用的幣別與獎金發放幣別不同時，才需要分開設定。
Q業務員離職或轉職時，系統需要做哪些處理？

每日同步 Job 偵測到業務員在內部系統停用後，會自動執行以下動作：

  1. 將 TCP_Salesperson.IsActive 設為 false，並填入 DeactivatedAt（時間）與 DeactivatedReason（Resigned / Transferred / Other）。
  2. 將該業務員所有 Active 狀態的 Plan，自動標記為 NeedsAttention，並填入說明。
  3. 在 TCP_PendingAction 建立待處理通知，提醒相關負責人（Gatekeeper 或主管）處理 Sales ID 歸屬及 Plan 狀態。

負責人收到通知後，需手動確認：

  • 原有 Sales ID 是否需要轉移給其他業務員（在對應 Plan 的 Sales ID 設定中調整）。
  • 相關 Plan 是否要關閉（將 PlanStatus 改為 Closed）。
  • 是否需要設定暫代（見第六節）。
QSales ID 的 AssignmentType 要設成什麼？
AssignmentType說明同步行為
Active（預設） 正式業績歸屬，計入 IND / NOACC 獎金計算 同步 Job 自動帶入對應 Plan 的 TCP_PlanSalesId
Administrative 行政歸屬用途，不計入任何獎金 同步 Job 不會帶入 TCP_PlanSalesId

通常一個業務員的所有 Sales ID 都設為 Active。若某個 ID 僅為系統掛名用途（例如某歷史區碼）而非真實業績歸屬，才設為 Administrative。

二、Commission Plan 建立與設定

Q一位業務員可以有幾個 Plan？什麼情況下需要多個 Plan？

一位業務員可以有任意數量的 Plan，每個 Plan 是一條獨立的計算線，擁有各自的業績來源、CR、Quota 設定。常見的多 Plan 情境：

情境建議 Plan 組合
業務員同時負責個人業績，並管轄下屬業績 IND Plan（個人業績） + LEADER Plan（管轄業績）
業務員有一部分客戶是新開發（NoAcc），其餘是既有客戶 IND Plan（既有業績）+ NOACC Plan（新客戶業績）
主管依業績來源拆分為 Sector A 和 Sector B，各自有不同 Quota 兩個 IND Plan，各自綁定對應的 Sales ID
區域主管需要依地區或產品線匯總業績 一個 RS Plan（報表來源）
每個 Plan 的最終獎金會匯總至 TCP_BonusSummary，業務員月底看到的是所有 Plan 的合計。
Q四種 Plan Type（IND / LEADER / RS / NOACC）如何選擇？
Plan Type適用情境業績來源
IND 一般業務員，業績以個人 Sales ID 計算 TCP_PlanSalesId（系統自動同步，可人工調整）
LEADER 主管業績，手動指定一組 Sales ID 加總 TCP_PlanSalesId（完全人工維護）
RS 區域/產品線彙總業績，依報表來源計算 Sales by Region / Sales by Product / My Sales Force（可組合）
NOACC 新客戶開發業務，CR 依客戶新舊分三段計算 TCP_PlanSalesId（系統自動同步，可人工調整）
IND 與 NOACC 的 Sales ID 來源邏輯完全相同，差異只在 CR 計算方式：NOACC 依客戶新舊分 Existing / New_Y1 / New_Y2 三段費率。
Q三種計算制度（Quota / Fixed / QuotaFX）要選哪一個？
制度適用情境獎金公式Over Quota 加發
Quota 制 一般業務員，有年度業績目標 出貨（本地幣別）× CR% ✅ 適用
固定制 主管另定任務型 CR，不設年度 Quota 出貨（本地幣別）× CR% ❌ 不適用
QuotaFX 制 業績以外幣為主，需鎖定固定匯率保護業務員收益 出貨（外幣）× CR% × 固定匯率 → 本地幣別 ✅ 適用（達成率以外幣計算）
固定制不適用 Over Quota 加發，年終獎金與績效以底薪計算（非 TCP）。既有客戶 CR ≤ 1%；新客戶第一年 ≤ 3%；第二年 ≤ 2%。
QQuotaFX 制（固定匯率制）的設定步驟是什麼？
  1. 在 Plan 的「計算制度」選擇 QuotaFX。
  2. 填寫 FXCurrency：業績計算使用的外幣幣別（例：USD）。
  3. 填寫 FXRate：固定匯率（例：32.0000 代表 1 USD = 32 TWD）。此匯率由負責人與業務員協議後填入，鎖定全年不變。
  4. 填寫 AnnualQuota：年度 Quota 以外幣填寫（對應 FXCurrency），例如 1,000,000 USD。
  5. 每月上傳 CR 時，只需上傳 CR%（不含匯率部分），系統計算時會自動乘上 FXRate。
報表業績欄位固定顯示外幣，不換算為本地幣別。最終獎金發放時才轉為業務員的 BonusCurrency。不要將 FXRate 預乘進 CR%，系統會自動處理。
QAnnualQuota 和 AnnualVariablePay 分別要填什麼？
欄位填寫說明用途適用制度
AnnualQuota 年度業績目標金額。QuotaFX 以外幣填寫；其他制度以本地幣別填寫。 計算 YTM 達成率；Over Quota 加發基準 Quota 制、QuotaFX 制
AnnualVariablePay 年度 Variable Pay（獎金部分）。系統預設值為 1,000,000（TWD）。由負責人依薪資規範填入。 僅用於計算全年所得上限（TCP × 5 或 × 3）；不用於推算 CR，不影響每月計算 Quota 制、QuotaFX 制
AnnualVariablePay 不影響每月 CR 計算。底薪為個資，不進入本系統，CR 由負責人在系統外計算後上傳。
Q備註（Remark）欄位需要填嗎？

Remark 為選填欄位，可省略。方案的主要識別依據為「業務員 + Plan Type + 年份」的組合。

建議在以下情況填寫備註以利後續查詢：

  • 同一業務員同年有多個相同 Plan Type（例如兩個 IND Plan），備註說明各自負責的範圍。
  • 特殊安排，例如：暫代期間、試用期、特案核准。
  • 主管指示的任何補充說明。

三、Sales ID 設定

QIND / NOACC Plan 的 Sales ID 需要手動設定嗎？

一般情況下不需要。每日同步 Job 會自動從公司內部系統讀取業務員的 Sales ID（AssignmentType = Active），寫入 TCP_PlanSalesId（DataSource = Auto）。

以下情況才需要手動介入：

  • 某個 Sales ID 雖然歸屬該業務員，但不應計入獎金（例如行政用途的舊碼）→ 在 Sales ID 設定頁將其移除。
  • 業務員名下有多個 ID，其中一個需要分配給其他 Plan（例如另一個 IND Plan）→ 從本 Plan 移除，並到另一個 Plan 手動加入。
Q如何移除一個不應計算的 Auto Sales ID？移除後資料還在嗎？

在 Plan 的「Sales ID 設定」頁面，找到該筆記錄，點擊「移除」。

移除行為依 DataSource 不同而有差異：

DataSource移除動作顯示結果
Auto（系統同步） 系統填入 ValidToYear / ValidToMonth（當下年月），標記結束時間；資料保留 該筆以灰底顯示，標記「已失效」
Manual（人工新增） 直接從資料庫刪除（Hard Delete） 該筆不再顯示
Auto 記錄保留是為了稽核用途，日後可追溯「這個 ID 在哪個時間點被移出此 Plan」。
QLEADER Plan 要如何設定 Sales ID？

LEADER Plan 的 Sales ID 完全人工維護，系統不自動帶入任何記錄。

  1. 在 Plan 的「Sales ID 設定」頁面，點擊「新增 Sales ID」。
  2. 輸入 Sales ID 字串。
  3. 設定 ValidFromYear / ValidFromMonth：此 ID 開始計算業績的年月。
  4. 如果已知結束月份（例如某下屬預計年中離職），可填入 ValidToYear / ValidToMonth；未知則留空（null = 至今有效）。
  5. 填寫備註說明此 ID 的來由。
ValidFromYear/Month 與 ValidToYear/Month 都是整數欄位，月份填 1–12。例如：2026 年 4 月起生效，就填 ValidFromYear=2026、ValidFromMonth=4。
Q某個 Sales ID 在年中換人（例如 1–3 月是 A 業務，4–12 月是 B 業務），要如何設定？
  1. 在 A 業務的 Plan 中，找到該 Sales ID 的 Auto 記錄，移除（系統會填入 ValidTo = 3 月）。
  2. 在 B 業務的 Plan 中，手動新增該 Sales ID，設定 ValidFromYear=2026、ValidFromMonth=4，ValidTo 留空。

計算引擎會依 ValidFromYear/Month ~ ValidToYear/Month 的有效範圍篩選每月適用的 Sales ID，因此只要有效期間設定正確，同一個 Sales ID 在不同月份歸屬不同業務員是沒有問題的。

同一個 Sales ID 在同一個月份不應同時歸屬兩個 Plan，否則業績會被重複計算。
QRS Plan 不需要設定 Sales ID，要設定什麼？

RS Plan 的業績來源是報表，而非 Sales ID。需要在「報表來源設定」選擇一或多個報表來源，同一個 CR% 適用所有選用的報表：

SourceType說明
SalesByRegion依地區匯總的業績報表
SalesByProduct依產品線匯總的業績報表
MySalesForce管轄下屬銷售力彙總報表

三種來源可以任意組合，例如同時勾選 SalesByRegion + SalesByProduct。

四、每月 CR（Commission Rate）上傳

QCR 為什麼需要手動上傳？系統不能自動計算嗎？

所有制度（Quota / Fixed / QuotaFX）的 CR% 均由負責人在系統外依薪資規範算好後手動上傳，系統本身不計算 CR。

原因：Quota 制的 CR 需依底薪推算（年度 Commission ÷ 年度 Quota），固定制的 CR 由主管依薪資任務設定，而底薪屬於個人薪資資料，不存入本系統。

上傳的 CR% 以小數表示，例如 1% 填入 0.0100；2.5% 填入 0.0250。
Q如何上傳每月 CR？
  1. 前往 Plan 的「每月 CR 設定」頁籤。
  2. 下載 Excel 範本（系統自動依 Plan Type 產生對應格式）。
  3. 在範本中填入每月的 CR%（及 NOACC 各客戶類型的 CR%）。
  4. 將填好的 Excel 拖放至上傳區或點擊選擇檔案後上傳。
  5. 系統解析後顯示預覽，確認無誤後送出。
也可以直接在頁面上的表格逐月輸入，不一定要透過 Excel。
Q修改某月 CR 後，後續月份會怎麼變？

修改某月的 CR% 後，該月之後的所有月份會自動覆蓋為相同值；修改月之前的月份不受影響。

例如修改 5 月 CR% 為 0.0120，則 5、6、7、8、9、10、11、12 月全部變為 0.0120，1–4 月維持原值不變。

若要每個月設定不同的 CR%，需要逐月個別修改（後修改的月份會再次向後覆蓋）。

此規則同樣適用於 MinAchievementRate（發放門檻）的修改。
QNOACC Plan 的 CR 要填幾組？

每個月需填寫 3 組 CR%，對應三種客戶類型：

CustomerType說明CR 上限（依規範）
Existing既有客戶≤ 1%
New_Y1新客戶第一年≤ 3%
New_Y2新客戶第二年≤ 2%

計算時系統依每筆業績的客戶屬性（新舊判斷來自現有交易記錄）套用對應的 CR%，三段業績加總即為當月 Normal Incentive。

QQuotaFX Plan 上傳 CR 時，需要把匯率乘進去嗎？

不需要。上傳時只填入 CR%（不含匯率），系統計算時會自動依 Plan 上設定的 FXRate 相乘：

Effective CR = CR%（上傳值）× FXRate（Plan 設定）

例如上傳 CR% = 0.0100，Plan 設定 FXRate = 32.0，計算引擎實際使用 Effective CR = 0.32（即 0.01 × 32）。

若將匯率預乘進 CR% 再上傳，會導致重複計算，獎金金額會錯誤。

五、發放門檻（MinAchievementRate）

QMinAchievementRate 是什麼？

Normal Incentive 的每月發放條件：YTM（Year-to-Month 年度累計）業績達成率需達到此門檻，才發放當月獎金。

  • 預設值：70%（0.70）
  • 若當月 YTM 達成率未達門檻，當月計算所得的獎金暫扣，待達標後釋放。
  • 例如 1–4 月均未達 70%，到 5 月 YTM 達到 75%，則 1–5 月的暫扣獎金在 5 月份一併釋放。
Q如何調整某個 Plan 的發放門檻？
  1. 前往 Plan 的「每月 CR 設定」頁籤。
  2. 找到要調整的月份，修改 MinAchievementRate 欄位（填 0.00 ~ 1.00 之間的小數，例如 60% 填 0.60）。
  3. 修改後，該月及之後的所有月份自動覆蓋為相同值（與 CR% 的覆蓋邏輯相同）。
若某業務員年度目標偏高，主管可考慮降低門檻（例如 60%）以確保業務員在達標前仍有部分獎金激勵。也可設為 0 代表不設門檻，每月均發放。

六、暫代設定（TempCoverage）

Q什麼情況下需要設定暫代（TempCoverage）？

當某業務員離職或轉職，新人尚未到位或仍在試用期時，由現有業務員暫時接手對應的 Sales ID。

暫代設定的特性：

  • 暫代期間 CR = 原 CR × 50%（依規範固定）
  • 暫代期間達成 Over 100% Quota，不額外加發 Over Quota 獎金
  • 暫代與業務員本身的正式 Plan 分開計算，不互相影響
Q如何設定暫代？
  1. 前往執行暫代的業務員的 Plan 頁面，開啟「暫代設定」。
  2. 填入被暫代的 Sales ID。
  3. 填入 StartDate（暫代開始日）。
  4. 填入 TempQuota（暫代期間分配的 Quota 金額）。
  5. EndDate 暫時留空，等新人正式確認開始領獎金後，再回來填入結束日。
EndDate 不自動推算，須由負責人在新人試用期確認通過、正式接手後手動填入。不要猜測日期，等確認再填。

Q如何為特定業務員開啟或關閉某個模組？

  1. 前往「業務員設定」，找到目標業務員，進入「模組設定」頁面。
  2. 找到要調整的模組，切換啟用/停用狀態。
  3. 填入設定原因（Note），方便日後稽核。
  4. 儲存後，下次計算引擎執行時即套用個人設定。
個人設定以年份為單位。若需要只在特定年份有效，設定時注意年份欄位。

八、扣款機制與排除清單

8.1 Overdue AR（逾期應收帳款）
QOverdue AR 是怎麼觸發扣款的？
逾期狀態扣款方式
逾期 > 30 天保留 100% 相關業績的獎金，等待付款
逾期 > 90 天額外再保留 100%，合計保留 200%

客戶付清款項後，系統將 Status 更新為 FullyPaid，保留的獎金在下月釋放。

Overdue AR 資料由計算引擎自動從財務系統取得，無需手動輸入。若有爭議，可在備註欄說明，並聯絡財務確認。
8.2 壞帳（Bad Debt）
Q壞帳如何從逾期 AR 轉入？

當客戶確認支票跳票或無法收回款項時，財務人員將對應的 Overdue AR 轉為壞帳：

  1. 在逾期 AR 記錄中，點擊「認定壞帳」，選擇原因（BounceCheck / ConfirmedLoss）。
  2. 系統自動在 TCP_BadDebt 建立記錄，並計算扣款金額（原銷售額 × 2 倍業績獎金）。
  3. 扣款金額在下月的 BonusSummary 中以 BadDebtDeduction 項目扣除。
8.3 COGS 扣款
QCOGS 扣款在什麼情況下發生？
觸發條件扣款時機
訂單取消（PT 類產品）次月扣除
訂單延遲超過半年未出貨到期月扣除

扣款金額：（業績 − 品項成本）× CR

COGS 資料由 SCM 人員透過系統提報，填入訂單號、料號、成本金額及觸發原因。若訂單後來正常出貨，可設定 Status = Reversed 取消扣款。

8.4 Low GP 低毛利
Q低毛利如何影響獎金？
E2E GP%業績獎金認列比例
10% ~ 15%只認列 50%
≤ 10%不計入獎金
> 15%正常認列（不受影響）

E2E GP% = （E2E Sales − E2E Cost）÷ E2E Sales，Cost 包含 COGS + Landing Cost。系統自動從 eManager 取得 GP 資料計算，無需手動輸入。

8.5 業務借貸（ATW 專屬）
Q業務借貸如何設定與追蹤？
  1. 借出時，在系統建立借貸記錄：填入業務員、借出日、料號、數量、單位成本。
  2. 系統自動計算 DueDate（借出日 +90 天）。
  3. 若需延期（最多 +30 天），填入主管簽核單號，系統更新 ExtendedDueDate。
  4. 歸還或賣出時，更新 Status（Returned / Sold）並填入 ReturnedAt。
  5. 若到期仍未歸還或賣出（Overdue），系統在到期月從業績獎金扣除成本 100%（TotalCost）。
業務借貸模組僅適用 ATW。HQDC / BO 業務員的頁面不會顯示此功能。
8.6 排除清單（事前規則）
Q什麼是排除清單？什麼時候需要設定？

排除清單是事前設定的豁免規則，讓計算引擎在產生扣款記錄前，先比對清單，符合條件的訂單/客戶/料號直接略過，不產生扣款。

適用情境：

  • Low GP 排除：某訂單雖然毛利低，但已獲得主管核准特案處理，不應扣款。
  • 壞帳排除：某客戶的帳款已由總部另行處理，不由業務員承擔。
  • 借貨排除：某料號屬於展示品，不適用借貨扣款規則。
排除清單僅影響「未來」的計算。對於已經產生的扣款記錄，須使用「事後標記排除」（IsExcluded）方式處理。
Q如何新增排除規則？各類型的排除維度是什麼？

前往「系統設定 → 扣款排除規則」，選擇對應類型新增：

排除類型可選排除維度ScopeValue 填入
Low GP 排除規則 Order（特定訂單）
Customer（特定客戶所有訂單）		 OrderNo 或 CustomerId
壞帳排除規則 Invoice（特定發票）
Customer（特定客戶）		 InvoiceNo 或 CustomerId
借貨排除規則 Item（特定料號）
Salesperson（特定業務員）		 ItemNo 或 SalespersonId

每條規則需填入：排除維度、對應值、排除原因、核准人 AD 帳號。規則建立後 IsActive 預設啟用；停用後資料保留供稽核，不再影響新計算。

Q已經產生的扣款記錄，發現有誤要如何排除？

對已存在的扣款明細，使用事後標記排除：

  1. 在對應的扣款明細清單（Low GP / 壞帳 / 借貨）找到目標記錄。
  2. 點擊「標記排除」，填入 ExclusionReason（排除原因說明）。
  3. 系統自動記錄 ExcludedBy（操作者）與 ExcludedAt（時間）。
  4. 下次計算引擎執行時，IsExcluded = true 的記錄不計入扣款。
事後排除只影響「未來的計算結果」，已發放的 BonusSummary 需要重新計算才能更新。如需補發，請聯絡系統管理員重算。

九、獎金異常通知

Q獎金異常通知的觸發條件是什麼？

當計算引擎產生的單月獎金（GrossIncentive）超過設定的門檻金額時，系統自動：

  • 發送通知信給設定的收件人
  • 在 TCP_BonusAlert 建立記錄（含金額快照、門檻快照、收件人快照）
快照設計確保日後修改通知設定，不影響歷史記錄的可追溯性。
Q如何設定各 Site 的獎金異常通知門檻與收件人？
  1. 前往「系統設定 → 獎金異常通知」。
  2. 選擇要設定的 Site（ATW / HQDC / BO）。
  3. 填入 AlertThreshold（觸發門檻金額）。幣別由 Site 固定（ATW = TWD），無法修改。
  4. 填入 NotifiedTo：以分號分隔的 AD 帳號或 Email，例如 admin@test.com;manager@test.com。
  5. 確認 IsEnabled 已勾選，儲存。

各 Site 可設定不同的門檻與不同的通知對象，互不影響。

Q收到異常通知後，要在哪裡確認審閱？
  1. 前往「系統設定 → 獎金異常通知 → 通知記錄」（或從通知信的連結進入）。
  2. 找到對應的通知記錄，查看觸發時的獎金金額與門檻快照。
  3. 確認屬於正常（例如大單出貨）後，點擊「標記已審閱」，可選填備註說明原因。
  4. 系統自動記錄 ReviewedBy（AD 帳號）與 ReviewedAt（時間）。
建議每月收到通知後及時審閱，避免積壓，也讓財務審核更容易追蹤。

10.1 Design-in Win 獎勵
QDesign-in Win 獎勵有哪些階段，各要設定什麼？

十一、年度結算

QOver 100% Quota 獎金什麼時候結算？怎麼設定？

Over Quota 獎金為年結（每年一次），由計算引擎在年底執行時自動計算並寫入 TCP_OverQuotaIncentive，無需手動輸入業績或公式。

需要確認的前置設定：

  • Plan 的 AnnualQuota 已正確填入（這是計算達成率的基準）
  • 業務員的 Role 已正確設定（影響加成比率與全年上限）
  • 業務員 年底仍在職（結算時須在職才能領取）
  • 模組 OVER_QUOTA 已啟用（Quota / QuotaFX 制自動適用，Fixed 制不適用）
退貨追回：若客戶於次年第一季前取消訂單退貨，系統會在退貨確認後從後續月份追回相應獎金。
Q全年所得上限（AnnualEarningCap）是怎麼計算的？
角色上限公式
SalesAnnualVariablePay × 5 倍（TCP × 5）
Leader / Sales ManagerAnnualVariablePay × 3 倍（TCP × 3）

全年所得上限包含：Normal Incentive、Design-in Win、Service Incentive、Over Quota Incentive 及 KPI 獎金的年度合計。超過上限的部分不發放。

AnnualVariablePay 是各 Plan 分別設定的，若業務員有多個 Plan，需確認各 Plan 的 AnnualVariablePay 加總符合薪資規範。AnnualVariablePay 由負責人自行填入，系統不自動推算。

十二、異常狀況處理

QPlan 狀態顯示「NeedsAttention」要怎麼處理？

NeedsAttention 通常由以下情況自動觸發：

  • 業務員已離職或停用（最常見原因）
  • 系統偵測到設定異常需要人工確認

處理步驟：

  1. 查看 TCP_PendingAction 中的待處理通知，了解具體原因。
  2. 確認 Sales ID 歸屬是否需要調整（轉移給其他業務員）。
  3. 若此 Plan 確認不再使用，將 PlanStatus 改為 Closed，填入 StatusRemark 說明原因。
  4. 若此 Plan 繼續有效（例如業務員僅轉職），更新相關設定後，將 PlanStatus 手動改回 Active。
Q發現某月獎金計算有誤，可以重新計算嗎？

可以，但需依狀態操作：

BonusSummary 狀態處理方式
Draft（草稿）可直接觸發重算，系統重新執行計算引擎並更新結果
Approved（已審核）需先退回為 Draft 狀態，再重算（須由有權限的主管操作）
Paid（已發放）不可直接修改；若有差異需在下月以補扣款或補發方式處理，並在備註記錄原因
所有狀態異動都會記錄在 TCP_AuditLog，包含異動前後值、操作者、時間。
Q如何查詢某筆設定的歷史異動記錄？

系統的 TCP_AuditLog 記錄所有資料的異動，包含：建立、修改、刪除、審核、退回、覆寫等操作。

查詢方式：在各設定頁面的右上角通常有「查看歷史」功能，或至「系統設定 → 稽核紀錄」，依以下條件篩選：

  • EntityType：要查詢的資料表（例如 TCP_CommissionPlan、TCP_MonthlyRate）
  • EntityId：對應記錄的 ID
  • 日期範圍
  • 操作者 AD 帳號

每筆記錄會顯示異動前後的完整欄位值（JSON 格式）。

Q年度初，新一年的設定要做什麼？
  1. 新增年度 Plan：為每位業務員新增本年度的 Commission Plan（Plan Type、計算制度、AnnualQuota、AnnualVariablePay）。若與上年度相同，可從上年度複製後修改。
  2. Sales ID 同步確認：等待每日同步 Job 執行後，確認 IND / NOACC Plan 的 Sales ID 已正確同步帶入；LEADER Plan 手動維護 Sales ID。
  3. 上傳 CR：依薪資規範計算好 CR% 後，上傳至各 Plan 的每月 CR 設定（可一次上傳全年 12 個月，或逐月上傳）。
  4. 確認模組開關：確認各業務員的個人模組設定是否需要沿用或調整。
  5. 更新通知設定：如門檻或通知人員有異動，在「獎金異常通知」頁面更新。
