TCP Platform — 操作指南

版本: v2.0  |  更新日期: 2026-05-26  |  適用對象: 系統管理員 / 業務操作人員

1. 平台功能導覽

TCP Platform 以 Hub 首頁（/Admin/TcpPlatform）為入口，提供以下四個功能頁面。

📤
Upload
上傳年度業務員設定 Excel（Commission Rate / Sales ID Config / RS / Mapping）。支援預覽編輯、逐 Sheet 確認後匯入。
🔍
Data View
查詢目前 DB 中的設定資料，可直接逐筆 Edit / Delete，並在 Overview Tab 查看整合 Quota 資訊。
🌳
Org Hierarchy
管理業務組織樹狀結構，支援新增/編輯/刪除/移動節點，及 Excel 批次匯入。
📊
（規劃中）
Incentive & Penalty、Manual Adjustment 等功能正在規劃中。
何時用 Upload？何時用 Data View？
年度初次建立資料或大量更新 → 用 Upload（Excel 批次匯入）。
查詢現況或個別修改幾筆資料 → 用 Data View（直接在畫面上 Edit/Delete）。

2.1 步驟說明

  • 選擇 Year 與 Site
    Year 下拉依目前月份自動提供選項（1–3 月含上一年；10–12 月含下一年）。Site 選單從 DB 動態載入，必選，選完後 Drop Zone 才會就緒。
  • 準備 Excel 檔案
    格式必須符合標準範本（可從頁面下載 Download Template）。需包含 4 個 Sheet：Commission Rate、Sales ID Config、RS、Mapping（Sheet 名稱不分大小寫，支援別名）。
  • 拖放或點擊上傳
    將 Excel 拖入 Drop Zone，或點擊選取檔案。上傳後自動呼叫 ParsePreview（不寫入 DB）。
  • 確認 Preview 資料
    系統顯示 4 個 Sheet Tab。有錯誤的 Tab 會出現 ⚠ 圖示，錯誤儲存格以紅底白字標記。常見錯誤：Sales ID 不存在系統中、RS Report 名稱填錯、RS 維度值不在 DB 選項內。
  • （視需要）編輯資料
    點擊每行的 Edit 按鈕可修改儲存格。RS Sheet 的 Report、FOB_Local 為靜態下拉；Region / Entity / Sector / Prod_Group 為動態下拉（依 Report 選項過濾）。
  • Confirm 每個 Sheet
    每個 Tab 右下角有 Confirm This Sheet 按鈕。Confirm 前系統會再次驗證所有資料；有錯誤則無法 Confirm。Confirm 後 Tab 鎖定（Edit 按鈕消失）。
  • Import
    全部 Sheet 確認後，頁面底部出現綠色大按鈕 Import All Confirmed Data。點擊後寫入 DB。若無任何錯誤，也可點擊 Skip Review & Import 跳過逐 Sheet 確認。

4.1 Excel 批次匯入

  • 下載範本
    點擊 Download Template，系統產生含現有資料的 Excel 範本（可作為基礎修改）。
  • 填寫 Excel
    必填欄位：Email。選填：Display_Name、Role_Name、Parent_Email（填上一層的 Email；空白 = Root）、Sort_Order。Email 須存在於 EZUser 系統中。
  • 上傳
    點擊 Import Excel 上傳填寫好的檔案，系統依 Email 建立樹狀關係。
Org Hierarchy 無年份概念：組織樹資料不依年份切換，所有年度共用同一份組織架構。

5.1 Commission Rate — 欄位說明

Commission Rate Sheet 使用雙行表頭（第一行分組名稱，第二行子欄位名稱）。

Commission Type 四種類型

類型適用對象Sales ID 來源需要設定 Sales ID Config？
IND 一般個人業務員 系統自動同步（eManager） 不需要（自動使用本人 Sales ID）
NOACC 無個人帳號的業務員，邏輯同 IND 系統自動同步（eManager） 不需要（但支援 Delta 調整）
LEADER 主管或多 Sales ID 負責人 完全依照 Sales ID Config 設定 必須設定（Full-truth 模式）
RS Report-based 業務員，依報表維度計算 不使用 Sales ID 不適用（改設定 RS Sheet）

門檻欄位說明

欄位說明填寫格式
Achievement Rate Threshold年度累積達成率門檻，達到才套用 Standard CR%小數，e.g. 0.7 = 70%
Achievement Rate Threshold(Monthly)月度達成率門檻，啟用 Monthly CR% 的前提同上；與 Monthly CR%.Commission Rate 同時填才生效
GP毛利率門檻（視業務邏輯使用）小數；選填

CR% 欄位結構

區塊欄位說明
Standard CR%Commission Rate全年預設值，當月無個別設定時沿用
Jan ~ Dec各月份個別覆蓋值，留空 = 沿用 Commission Rate
Monthly CR%Commission Rate未達月門檻時的預設費率
Jan ~ Dec各月份個別覆蓋值，留空 = 沿用 Monthly Commission Rate
Monthly CR% 注意：Achievement Rate Threshold(Monthly) 和 Monthly CR%.Commission Rate 必須同時填寫，任一留空則整個 Monthly CR% 區塊不儲存。

5.2 Sales ID Config — 欄位說明與匯入邏輯

Jan~Dec 欄位代表該 Sales ID 在該月是否啟用計算業績（isActive）：1 或任意非空值 = 啟用；0 或留空 = 停用。

匯入邏輯依 Commission Type 不同

Commission Type情況動作
IND / NOACC
Delta 模式		 該 Email 出現，至少一月 = 1INSERT / UPDATE 該 Sales_Id
該 Email 出現，所有月份空白DELETE 該 Sales_Id（表示要移除）
該 Email 未出現在 Sheet不動（系統 Job 維護基底，不受影響）
LEADER
Full-truth 模式		 該 Email 出現，至少一月 = 1INSERT / UPDATE 該 Sales_Id
該 Email 出現，所有月份空白IGNORE（忽略，不刪不改）
該 Email 未出現在 SheetDELETE 該 Email 所有舊有 Sales_Id
實務建議：LEADER 類型每次上傳，等同重新宣告所有有效 Sales ID；未列出的會被刪除。確保每次都帶完整清單。

常見情境

情境設定方式
全年啟用Jan~Dec 全填 1
下半年才啟用Jan~Jun 填 0，Jul~Dec 填 1
7月換新 Sales ID舊 Sales ID：Jan~Jun 填 1，Jul~Dec 填 0；新 Sales ID：Jan~Jun 填 0，Jul~Dec 填 1
IND 要移除某 Sales ID填一行該 Sales ID，Jan~Dec 全空白（觸發 DELETE）

5.4 Mapping — 欄位說明

設定業績觀看權限：誰可以看到誰的業績資料（與管理階層無關）。

欄位說明範例
Email觀看者（要開放觀看權限的人）manager@co.com
Sales Email被觀看的業務員 Emailsales@co.com
範例：主管 A 要看業務員 B 和 C → 填兩行：Email = A，Sales Email 分別填 B、C。
移除觀看權限：系統匯入只做 UPSERT，不會自動刪除舊記錄。若需移除特定筆，請至 Data View → Mapping Tab 逐筆 Delete，或於下次上傳後在 Upload History 刪除整批再重傳。

5.5 Group Name — 多重計算方式

Group Name 是讓同一位業務員支援多種獎金計算方式的關聯鍵。Commission Rate、Sales ID Config、RS 三張 Sheet 透過 Email + Group Name 做對應。

情境設定方式
業務員只有一種計算方式Group Name 留空即可
業務員有兩種計算方式Commission Rate 填兩行，Group Name 分別填不同名稱（e.g. GroupA / GroupB）；Sales ID Config 對應各自 Group Name 分配 Sales ID
注意：三張 Sheet 中填入的 Group Name 必須完全一致（區分大小寫），否則系統無法正確對應。建議統一使用簡短的英文命名，例如 CR9、TW、ProductA。
