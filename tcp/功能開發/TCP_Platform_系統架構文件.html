版本: v2.0  |  更新日期: 2026-05-25  |  適用專案: eManagerCoreAdmin (TcpPlatform branch)

1. 系統概覽

TCP Platform 是 eManagerCoreAdmin 後台系統中的 TCP 獎金平台管理模組，提供以下功能：

  • Upload：上傳年度業務員設定 Excel，包含 Commission Rate、Sales ID Config、RS、Mapping 四個 Sheet。支援預覽編輯、逐 Sheet Confirm、Cell Error 紅底高亮。
  • Org Hierarchy：管理業務組織樹狀結構，支援新增/編輯/刪除/移動節點，及 Excel 批次匯入。
  • Data View：以 Year + Site 查詢目前 DB 中的設定資料，提供 5 個 Tab（Commission Rate / Sales ID Config / Mapping / RS / Overview），支援 Edit / Delete 操作及 Quota 整合顯示。
  • Incentive & Penalty（規劃中）：激勵與懲罰設定。
  • Manual Adjustment（規劃中）：人工調整。

入口頁面：/Admin/TcpPlatform

3. 功能模組

3.1 Upload — 設定檔上傳

流程說明

  1. 使用者選擇 Year（下拉，當年 ± 上一年 1-3月 / 下一年 10-12月）與 Site（從 DB 動態載入）。
  2. 拖放或點擊 Drop Zone 選擇 Excel 檔案，前端呼叫 POST /api/TcpUpload/ParsePreview。
  3. Server 解析並回傳各 Sheet 預覽資料（不寫 DB）；回傳包含 CellErrors 清單，前端標記紅底錯誤儲存格、Tab 驚嘆號 icon。
  4. 使用者可在預覽中編輯資料列（依欄位型別顯示不同輸入控制項）。RS Sheet 的 Report / FOB_Local 使用靜態 select；Region / Entity / Sector / Prod_Group 使用動態 select（選項來自 GetRsOptions 快取）。
  5. 逐一 Confirm 每個 Sheet 前先執行 validateSheetBeforeConfirm() 重驗，有錯誤則阻擋。Confirm 後 Tab 鎖定、隱藏 Actions 欄。
  6. 全部確認後，或點擊 Skip Review & Import（需無錯誤），前端呼叫 POST /api/TcpUpload/ImportFromPreview 寫入 DB。
  7. 上傳紀錄可在 Upload History Modal 查看，支援按 YearId + Site 篩選及刪除。

Commission Rate Sheet — 雙行表頭解析

Commission Rate Sheet 使用兩行表頭（第 1 行為分組名稱，第 2 行為子欄位名稱）。解析後欄位名稱格式為 GroupName.SubName，例如：

  • Standard CR%.Commission Rate
  • Standard CR%.Jan ~ Standard CR%.Dec

3.2 Org Hierarchy — 組織樹管理

功能說明

  • 樹狀結構以 TCP_Sales_Org_Node 自我參照（Parent_Id）儲存。
  • 操作：新增 Root Node、新增子節點、編輯節點、刪除（不可刪有子節點）、移動節點（防止移到自身後代）。
  • 查看節點下所有 Sales IDs（GetDescendantSalesIds）。
  • Excel 批次匯入：下載範本（含現有資料）→ 填寫 → 上傳替換或補充。
  • 無年份概念：Controller 固定使用 DateTime.Now.Year，不需使用者選擇年度。

5. Commission Type 說明

類型說明Sales ID 來源Sales_ID_Config 用途
IND 個人業務員，每月佣金以自身 Sales ID 業績計算 系統每日 Job 從 eManager 自動同步 Delta 模式：僅紀錄要「調整」的部分（移除或新增）
NOACC 無專屬帳戶業務員，佣金邏輯同 IND 同 IND，系統自動同步 Delta 模式（同 IND）
LEADER 主管層，佣金以其負責範圍內多個 Sales ID 業績加總計算 完全依照 Sales_ID_Config 設定 Full-truth 模式：列表即為全部有效清單
RS Report-based Salesperson，依報表維度（Region/Entity 等）計算 不使用 Sales ID 不適用，RS Sheet 另行設定維度

6. Sales_ID_Config 匯入邏輯

Sales_ID_Config Sheet 的匯入行為依 Commission Rate Sheet 中對應人員的 Commission_Type 決定，不同模式有不同的增刪語意。Type 對應由 BuildTypeMap(preview) 從同批次 Commission_Rate sheet 建立 "email|groupname" → type 對照表，在 ImportSalesIDConfig 中分流。

IND / NOACC：Delta（差異）模式

情況動作
該 Email 出現在 Sales_ID_Config，且至少一個月份 = 1INSERT（新 Sales_Id）或 UPDATE（更新月份）
該 Email 出現在 Sales_ID_Config，但所有月份皆為空DELETE 該 Sales_Id（表示要移除這個 Sales_Id）
該 Email 未出現在 Sales_ID_Config不動（系統 Job 維護原有基底）

邏輯說明：IND/NOACC 人員的 Sales ID 基底由系統 Job 每日從 eManager 同步，上傳只記錄「例外」：要移除的列全部清空月份，要新增的填新 Sales Id。未列出的 Sales Id 不受影響。

LEADER：Full-truth（全真）模式

情況動作
該 Email 出現在 Sales_ID_Config，且至少一個月份 = 1INSERT（新 Sales_Id）或 UPDATE（更新月份）
該 Email 出現在 Sales_ID_Config，但所有月份皆為空IGNORE（忽略，不刪不加）
該 Email 未出現在 Sales_ID_ConfigDELETE 該 Email 所有既有 Sales_Id（不在清單即視為失效）

邏輯說明：LEADER 的 Sales ID 完全依照本次上傳的 Sheet 決定，未列出的 Sales Id 全部刪除。列出但全月份空值視為人工錯誤，忽略不處理。

RS

RS 類型不使用 Sales_ID_Config。其業績計算依 RS Sheet 設定的維度（Region/Entity/Sector/Prod_Group 等）從報表系統拉取。

7. RS Report 別名系統

RS Sheet 的 Report 欄位接受多種寫法（不分大小寫），系統統一正規化為標準值後再進行 enum 驗證與 DB 比對。

別名對應表

接受輸入（不分大小寫）正規化標準值
Region / Sales by Region / SalesByRegionSalesByRegion
Product / Sales by Product / SalesByProductSalesByProduct
My Sales Force / MySalesForceMySalesForce

實作位置

層次實作套用位置
Service（C#）NormalizeRsReport(string raw) + 靜態 RsReportAliases Dictionary（OrdinalIgnoreCase）ParsePreview 中 enum 驗證、rowsByReport grouping、CheckRsCol、ParseRSRow 共 4 處
前端（JS）normalizeRsReport(raw) + RS_REPORT_MAP object（key 全小寫）Preview 儲存格顯示、Confirm 重驗、RS Edit Dropdown

RS ParsePreview 兩層驗證

  1. 硬編碼 enum 驗證：Report ∈ {SalesByRegion, SalesByProduct, MySalesForce}；FOB_Local ∈ {Local, FOB}。不符合者加入 CellErrors。
  2. DB 維度比對：依 Report 類型查對應資料表，比對所有維度欄位是否存在：
    • SalesByRegion → Sales_Sector（region_id, entity_id, sector, prod_group）
    • SalesByProduct → SALES_PRODUCT（同上 + prod_divi）
    • MySalesForce → SALES_FORCE（Sales_Group 代替 sector）

前端處理

// renderPreview 後建立 cellErrorMap
cellErrorMap = {};    // { "SheetName|ColName" → { "value_lc": true } }
sheetsWithErrors = {}; // { sheetName: true }

(data.cellErrors || []).forEach(function(e) {
    sheetsWithErrors[e.sheet] = true;
    var key = e.sheet + '|' + e.column;
    if (!cellErrorMap[key]) cellErrorMap[key] = {};
    (e.values || []).forEach(function(v) {
        if (v) cellErrorMap[key][v.toLowerCase()] = true;
    });
});
  • 紅底白字 CSS：.cell-error { background:#dc3545 !important; color:#fff !important; }
  • Tab 上顯示驚嘆號 icon：fa-exclamation-circle tab-error-icon（font-size:135%）
  • Skip Review 按鈕在有任何錯誤時 disabled

Confirm 前重驗（validateSheetBeforeConfirm）

點擊 Confirm 前掃描目前所有 rows，對照 cellErrorMap + rsOptions 重新驗證：

  • 一般 Sheet：比對 cellErrorMap 是否有錯誤值
  • RS Sheet：額外驗 Report enum、FOB_Local enum、4 個維度是否在 rsOptions 選項內
  • 更新 cellErrorMap、sheetsWithErrors、Tab error icon、btnImport disabled 狀態
  • 有錯誤則 toastr.error 並阻擋 Confirm

Group Name 使用規則

若同一業務員有兩種不同的 Commission Type 或 Rate 結構，可使用 Group Name 加以區分：

  • 第二結構：Group Name = "A"（或其他識別字）

10. UI 開發慣例

按鈕對齊

所有頁面的 .btn 一律在 <style> 區塊頂端加上：

.btn { display: inline-flex; align-items: center; justify-content: center; }

原因：Bootstrap 4 的 <button> 與 <a class="btn"> 垂直對齊行為不一致，inline-flex 是最可靠的統一解法。不要用 line-height 個別調整。

Modal Header 對齊

Bootstrap 4 的 .modal-header 預設 align-items:flex-start，會造成 X 按鈕偏上。解法：在 modal-header 的 style 屬性中完整宣告 flex 佈局：

style="background:#00467f; color:#fff; padding:12px 16px;
       display:flex; flex-direction:row; justify-content:space-between; align-items:center;"

Close 按鈕加上 style="color:#fff; opacity:1; margin:0; align-self:center;"。

不要只在 inline style 加 align-items:center，必須同時宣告 display:flex，否則不會覆蓋 Bootstrap class 的設定。

isActive 欄位顯示

Sales_ID_Config 和 RS 的 Jan~Dec 月份欄位在 View mode 使用圖示代替數字：

  • Active（非空值）：<i class="fa fa-check-circle" style="color:#27ae60;">
  • Inactive（空值/0）：<i class="fa fa-circle-o" style="color:#ccc;">

Table Row Hover

所有 Preview 和 DataView 資料表都要加：

tbody tr:hover td { background: #dce8f8; }

Year 下拉邏輯

Upload 與 DataView 頁面共用同一邏輯：

  • 預設顯示當年度
  • 1–3 月：額外加入上一年（方便年初補上傳）
  • 10–12 月：額外加入下一年（方便年底預設下一年）

Site 自動觸發

Upload、Org Hierarchy、Data View 三個頁面：Site 下拉 change 後自動呼叫對應 API，無需使用者另行點按鈕。

Razor 中的 CSS Animation

Razor View 中撰寫 CSS animation 時，@keyframes 必須寫成 @@keyframes，否則 Razor 會將 @ 視為 C# 表達式起始符號。

Preview 排序

ParsePreview 回傳的各 Sheet 資料，前端在 renderPreview 時先依 Email 欄 ascending 排序（localeCompare），方便使用者核對。
