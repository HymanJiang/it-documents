TCP 獎金平台 — 設定簡化分析

版本v1.0（2026-05-12）
目的釐清哪些設定真正需要人工操作，識別可自動化或合併的部分，提出精簡後的設定模型
適用系統設計討論、前端規劃參考

一、現有設定項目的分類

以「設定同仁實際需要做什麼」為視角，將所有設定項目依操作頻率與複雜度分類：

設定項目 頻率 現在由誰操作 能否自動化
新增業務員基本資料 一次性 同步 Job 自動帶入 ✅ 已自動
IND / NOACC 的 Sales ID 清單 自動維護 同步 Job 自動帶入 ✅ 已自動
為業務員建立 Commission Plan 每年一次 設定同仁手動建立 ⚡ 可大幅簡化
CR% 設定（12 個月） 每年一次（年中可能異動） 設定同仁批次上傳 ⚡ 可批次化
LEADER Plan 的下屬 Sales ID 異動時 設定同仁手動維護 ⚠️ 需人工，但少見
暫代設定（TempCoverage） 異動時 設定同仁手動建立 ⚠️ 需人工，但少見
模組開關（個人覆蓋） 異動時 設定同仁手動調整 ⚠️ 需人工，但少見
系統預設模組開關 一次性 系統管理員設定一次 ✅ 不需常改
最低達成率門檻（MinAchievementRate） 一次性（預設 70%） 建 Plan 時設定 ✅ 預設即可，不需每次填
結論：設定同仁每年真正需要做的事只有兩件——建立 Plan 與 上傳 CR%。 其他項目若能給好預設值，就不需要出現在主要流程裡。

二、現有設定的複雜度來源

造成複雜的設計

  • 建立 Plan 需填寫多個欄位，即使大多數情況下值都一樣
  • 「計算制度」與「Plan Type」概念重疊，需要選兩次
  • Quota 若由 Plan Type 推算，就不需要獨立欄位
  • MinAchievementRate 有預設值，但每次都要求確認
  • Variable Pay 很少改動，但出現在主流程中
  • CR% 以「逐月填入」呈現，視覺上像要填 12 個格子

已經夠簡單的設計

  • IND / NOACC 的 Sales ID 完全自動，無需操作
  • 業務員離職由 Job 自動標記，不需手動停用
  • 系統模組預設值統一設定後，個人不需逐一開啟
  • CR% 支援批次 Excel 上傳，一次搞定所有人

三、精簡後的設定模型

將所有設定分為三個層次，讓設定同仁只需要關心 Layer 1 與 Layer 2：

Layer 1 — 年度例行作業（每年 1～2 次）

這是設定同仁每年一定要做的事，應該做到最順暢：

步驟 1
確認業務員名單
系統自動同步，確認有無異動即可
›
步驟 2
為每人指定 Plan Type
IND / LEADER / RS / NOACC
›
步驟 3
批次上傳全員 CR%
一張 Excel，一次搞定全年
如果一位業務員今年的 Plan Type 跟去年相同，步驟 2 甚至可以省略—— 系統年初自動複製上一年的方案，讓設定同仁只需確認，有異動才修改。

Layer 2 — 異動處理（有需要才做）

情境 需要做什麼 複雜度
LEADER Plan 下屬成員異動 在該 Plan 的 Sales ID 清單中新增 / 移除 低（清單操作）
年中 CR% 調整 在設定總覽展開該月份直接修改 低（單格修改）
業務員暫代他人 建立 TempCoverage，填入起訖日與被暫代對象 中
特殊模組開啟（Service、政府補助等） 在業務員個人頁開啟對應模組開關 低
業務員離職 系統自動標記，負責人確認 Plan 狀態即可 低

Layer 3 — 系統管理（管理員一次性設定）

這些設定通常只做一次，之後不需要動：

  • 各 Site 的預設模組開關（AR、COGS、壞帳等是否全員啟用）
  • 獎金異常通知門檻與通知對象（TCP_BonusAlertConfig）
  • MinAchievementRate 預設值（預設 70%）

四、可以進一步簡化的具體建議

建議 1：年初自動複製上年方案

每年年初，系統自動將上一年所有 Active 方案複製為新年度草稿， 設定同仁只需「確認清單有無異動」，而不是從零開始建立每個人的 Plan。 有新人或角色異動才需要手動新增。

需要確認：跨年度複製時，CR% 是否也一起帶入作為參考值，還是留空等新一年上傳？

建議 2：CR% 改以「一人一列」的 Excel 上傳為主流程

目前逐月填入的 UI 讓設定看起來需要填很多格， 實際上大多數人全年 CR% 相同，只需要一個值。 建議 Excel 範本設計為：

業務員 Plan Type 全年相同 CR% 1月（如有差異） 2月 … 12月
張小明 IND 3.5% （空白＝沿用全年值）
李大華 IND 3.0% 3.0% … 4.0%

「全年相同」欄有值就套用全年；只有特定月份不同的人才需要逐月填。

建議 3：Plan Type 決定後，其他欄位自動帶入預設值

新增 Plan 時，選完 Plan Type 後，以下欄位應自動帶入，不需要設定同仁逐一確認：

欄位自動帶入的預設值
MinAchievementRate70%（可事後覆蓋）
BonusCurrency依業務員所屬 Site 帶入（ATW → TWD）
模組開關沿用系統預設（TCP_ModuleDefault）
Sales ID 來源IND / NOACC 自動同步；LEADER 手動（建完後再設定）

建議 4：將 LEADER 的 Sales ID 設定從新增 Plan 流程中移出

建立 LEADER Plan 時，不強制立即設定下屬 Sales ID。 讓設定同仁先把所有人的 Plan 建好、CR% 上傳完， 再統一回來處理 LEADER 的 Sales ID 清單。 避免新增一個 Plan 中途要跳去查下屬 ID 而打斷思路。

五、簡化後的年度設定流程摘要

採用上述建議後，設定同仁的年度例行工作可壓縮為：

動作 操作方式 預估時間
① 確認業務員名單（新人 / 離職） 系統自動同步後，設定同仁掃一眼清單 5 分鐘
② 確認 / 新增各人 Plan Type 系統帶入上年方案，只有異動的人需要手動調整 10 分鐘
③ 上傳全員 CR% 下載範本 → 填入 CR% → 上傳，一次完成 15 分鐘
目標：年度設定壓縮在 30 分鐘內完成。 剩下的時間只在有異動時才需要介入（LEADER 調整、暫代、CR% 年中修改）。
前提：建議 1（年初自動複製方案）需要確認業務規則—— 若某位業務員今年角色改變（例如從 Sales 升為 Leader）， 系統必須能識別並提示設定同仁手動確認，不能靜默複製舊方案。
