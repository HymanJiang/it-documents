一、專案背景與目標

1.1 背景

現有 TCP（Total Compensation Package）系統已無法滿足業務需求，主要問題如下：

  • 死碼糾纏：程式中存在大量已不使用的獎金計算邏輯，與現行邏輯相互影響，難以安全修改。
  • 資料不完整：資料表記錄欄位不足，無法支援完整的查詢與追溯。
  • 透明度不足：業務員無法自行查驗獎金計算明細，產生信任問題。
  • 設定過於複雜：舊有 Sales_Type 欄位混雜多種歷史邏輯，缺乏清晰規範。

1.2 目標

  • 以全新架構重建，完全取代現有系統。
  • 每筆獎金都有完整計算明細，業務員可自行對帳（透明化優先）。
  • 所有規則參數化，CR%、Quota、模組開關均存資料庫，不寫死在程式中。
  • 資料完整性：每個影響獎金的事件均留有記錄。
  • 獨立運作，未來直接替換舊系統。

二、獎金規範摘要

2.1 薪資結構

業務薪資採用 TCP（Total Compensation Package）制度：

TCP = 底薪（Base Salary）+ 業績獎金（Commission）

底薪為保障所得，業績獎金依 Commission Rate（CR）制度計算。

2.2 Commission Rate 制度

CR 上傳說明：所有制度的 CR% 均由負責人在系統外依薪資規範手動計算後，以每月費率表方式上傳至系統（TCP_MonthlyRate）。底薪為個資，不進入本系統，故系統不自動推算 CR。
制度CR 設定方式限制／說明
Quota 制 負責人依「年度 Commission ÷ 年度 Quota」於系統外算好後手動上傳
Commission 占 TCP 比例由各 BU 訂定，一般以 30% 為主

獎金公式：出貨（本地幣別）× CR%		 年終獎金、績效獎金、團隊獎金以 TCP 計算

三、系統設計決策

3.1 設計決策：CR 由外部手動上傳

設計決策：CR% 不在系統內計算
底薪（Base Salary）屬於個人薪資資料，不存入本系統。由於 Quota 制的 CR 需依底薪推算，固定制的 CR 亦由主管依薪資任務設定，所有制度的 CR% 均由負責人在系統外算好，以每月費率表方式手動上傳至 TCP_MonthlyRate。
AnnualVariablePay 欄位僅作為全年所得上限（TCP × 5 或 × 3）的參考依據，不用於推算 CR。

3.2 設計原則

  • 透明化優先：每筆獎金必須有完整計算明細，業務員可自行對帳。
  • 規則參數化：CR%、Quota、門檻值、模組開關全存資料庫，不寫死於程式。
  • 資料完整性：每個影響獎金的事件均需留有記錄（含異動前後值）。
  • 模組化設計：每種獎懲機制獨立，可彈性啟用/停用。

3.3 核心概念：一人多 Plan

每位業務員（AD 帳號）可擁有多個獎金方案（Commission Plan），每個 Plan 是一條獨立的計算線：

業務員（Salesperson）
  └── Plan A：IND，Quota 制，Sector A
  └── Plan B：NOACC，Fixed 制，新客戶開發
  └── Plan C：LEADER，Quota 制，管轄下屬業績
        ↓
每個 Plan 各自擁有：
  • 每月 CR 設定
  • 年度 Quota / Variable Pay
  • 適用的業績來源（Sales ID 清單 / 報表）

3.4 Plan Type 定義

設計決策：TCP_PlanSalesId 為所有 Plan 的統一 Sales ID 來源
IND / NOACC 由同步 Job 從 TCP_SalesId 自動帶入，並可人工調整；LEADER 完全人工維護。計算引擎一律從 TCP_PlanSalesId 讀取有效範圍內的 Sales ID，不直接讀取 TCP_SalesId。
Type業績來源特殊邏輯
IND TCP_PlanSalesId（由同步 Job 從 TCP_SalesId 自動帶入，可人工調整） 同步時只帶入 AssignmentType = Active 的 Sales ID；人工可移除不應計入獎金的 ID
LEADER TCP_PlanSalesId（完全人工維護） 設定者手動指定要納入計算的 Sales ID 清單與有效月份
RS Sales by Region / Sales by Product / My Sales Force 報表（可任意組合） 同一 CR% 適用所有選用報表；不使用 TCP_PlanSalesId
NOACC TCP_PlanSalesId（由同步 Job 從 TCP_SalesId 自動帶入，可人工調整） Sales ID 來源邏輯同 IND；CR 計算依客戶新舊分三段：
既有客戶 ≤ 1%
新客戶第一年 ≤ 3%
新客戶第二年 ≤ 2%
（新舊判斷來自現有交易記錄）
