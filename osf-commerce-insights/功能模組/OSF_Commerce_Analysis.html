OSF Commerce Insights — 程式碼分析報告

分析日期 2026-04-29 ｜ Repository / Service / Page / Model 全層分析

一、整體架構

標準 ASP.NET Core 分層：Presentation（Razor Page）→ Service → Repository（Dapper）→ Database（SQL Server）。

層級檔案路徑

DataModels / DTOModels/DataModels/OSFCommerce/、Models/DTO/OSFCommerceInsights/

二、Model 層

OSFCommerceQuery（查詢參數）

Year(int)、Currency(string)、Sector(string，"ALL"=全部)。

OSF_CommerceInsights（Insights 主資料，縱向 EAV 格式）

每筆 = 維度組合 × KPI × 時間的單一數值。欄位：HierarchyYear、Year、DateDimension（Jan…Dec/Total/YTM/YTMLocal）、Currency、Store、Region、Country（"ALL"=匯總）、KPI、Value。

OSF_CommerceInsightsKPI（KPI 定義與樣式）

PerformanceArea、KPI、Sort、FontColor、BackgroundColor、Floor（縮排層級，每層 ×10px）、DecimalPlaces、hasLocalCurrency、hasPercentage、DataSource。

OSF_CommerceInsightsHierarchy（層級結構）

Level（1=Store, 2=Region, 3=Country）、LevelName、Value（如 TW/APAC/ALL）、Sort、FontColor、LocalCurrency。

OSF_CommerceInsightsDto（Service 聚合 DTO）

一次打包三張表結果（oSF_CommerceInsights、KPIs、Hierarchies）供 PageModel 使用。另有舊版 OSFCommerceGetKpiDatasResponseDto（月份橫向展開格式）。

三、Repository 層

注入 IProjectReportHelper 取得連線，ORM 用 Dapper。OSFGetKpiDatas 有三條 SQL 路徑：

條件SQL 邏輯
Sector == "ALL"不篩 Sector，依 OSF_SectorSort.SectorSort 及 OSF_Commerce_Style.Sort 排序
Sector != "ALL" 且 USD加 O.Sector = @Sector 篩選
Sector != "ALL" 且非 USDUNION：本地幣別兩段（第二段 Sort not in 1,2,3 且用 OSF_SectorSort.Currency 篩），統一 ORDER BY Sort

KPI 查詢動態替換年份：KPI 含 "LastYear"/"CurrentYear" → 替換為實際年份（如 Revenue LastYear → Revenue 2025）。

四、Service 層

OSFGetKpiDatas：呼叫 Repository 取單一 UnitDto，包成 List 放入 Response。GetOSFCommerceInsights：同時呼叫 Insights/KPI/Hierarchy 三方法組成 DTO。（原 Region GroupBy 邏輯已註解，留 TODO。）

五、Presentation 層

PageModel 屬性：SelectedYearId/Currency/Store/Region/Country、Level。OnGet() 設預設年、取資料、初始化下拉（YearList 2024~當年、CurrencyList 從 Hierarchies 的 LocalCurrency 去重）。

OnGetDataAsync()（AJAX ?handler=Data）：取 DTO → 依 Level 篩 Hierarchies → 排序 KPIs → Currency 篩選 → YTM Local 處理（複製 YTM 資料標記為 YTMLocal）→ 依 Level 套維度篩選 → 回傳 JSON。

前端層級邏輯

Store 未選            → Level 1（Store 維度）
Store 已選, Region 未選 → Level 2（Region 維度）
Store + Region 皆選    → Level 3（Country 維度）

表格動態生成：維度欄 rowspan=KPI 數、PA 欄 rowspan=該 PA 的 KPI 數、KPI 欄套背景/字色/縮排；數值千分位 + 指定小數，百分比加 %。"ALL" 不可下鑽。

六、資料庫結構（推斷）

資料表用途
OSF_Commerce舊版 KPI（月份橫向展開）
OSF_Commerce_Style / OSF_SectorSort樣式設定 / Sector 排序
OSF_CommerceInsights新版 Insights（縱向 EAV）
OSF_CommerceInsightsKPIKPI 定義、排序、樣式
OSF_CommerceInsightsHierarchyStore/Region/Country 三層層級

七、資料流程

篩選器 → loadData() AJAX → OnGetDataAsync()
  → GetOSFCommerceInsights(Year)
      → OSF_CommerceInsights / KPI(年份替換) / Hierarchy
  ← DTO { data, KPIs, Hierarchies } → JSON
  → renderTable()（維度列 rowspan → KPI 列分組 → 填值 → formatNumber）

八、注意事項與潛在問題

1. YTM Local 資料重用：localData 為原始資料引用，修改 DateDimension 可能汙染原物件，建議深複製（Select new）。

2. Level 1 篩選不一致：維度篩用原始 filteredData（僅 Currency 篩），但回傳的是 combinedData，結果與回傳不一致。

3. UNION SQL 幣別：非 USD 第三路徑用 So.Currency=@Currency，OSF_SectorSort.Currency 欄意義需確認，避免與 OSF_Commerce.Currency 混淆。

4. 文字編碼：.cshtml.cs 部分中文註解亂碼，建議統一 UTF-8。

5. GroupBy TODO：OSFGetKpiDatas 有被註解的 Region GroupBy，未來分組需求可參考。
